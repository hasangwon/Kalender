# Play Console 등록 절차

하상원 님이 직접 진행하는 절차. 코드 쪽(AAB·키스토어·아이콘·스크린샷·방침 초안)은 Claude 가 준비한다.
콘솔 화면 문구는 바뀔 수 있으니 흐름 기준으로 본다. 작성 기준일 2026-10-19.

## A. 개발자 계정 등록 (며칠 걸리므로 가장 먼저)

1. 개발에 쓸 구글 계정으로 https://play.google.com/console/signup 접속. 이 계정이 개발자 계정의 주인이 된다.
2. 계정 유형 **개인** 선택. 조직 계정은 D-U-N-S 번호·사업자 서류가 필요하고, 개인 계정은 그 대신 아래 테스트 요건이 붙는다.
3. 개발자 이름(스토어 공개, iOS 와 맞춰 "하상원"), 연락 이메일·전화 등록 → 각각 인증 코드 확인. 무료 앱만 올리는 개인 계정은 이름·이메일만 공개된다.
4. 신원 확인: 정부 발급 신분증 사진 업로드. 결제 카드도 본인 명의. 정보가 틀리면 등록비는 환불되지 않는다.
5. 등록비 결제, 개발자 배포 계약 동의. 승인까지 보통 1~2일, 길면 며칠.

| 항목        | 값                                                          |
| ----------- | ----------------------------------------------------------- |
| 등록비      | 25달러, 1회                                                 |
| 신원 확인   | 정부 발급 신분증, 본인 명의 카드                            |
| 공개 정보   | 개발자 이름, 이메일                                         |
| 테스트 요건 | 2023-11-13 이후 개인 계정은 비공개 테스트 **12명 · 14일**   |

## B. 앱 만들기와 선언 항목

6. "앱 만들기": 앱 이름, 기본 언어 한국어, 앱, **무료** (유료로 바꿀 수 없지만 iOS 도 무료).
7. 대시보드 "앱 설정" 작업을 순서대로 채운다.

| 항목             | 답                                                                                          |
| ---------------- | ------------------------------------------------------------------------------------------- |
| 앱 액세스 권한   | 모든 기능이 제한 없이 이용 가능                                                              |
| 광고             | 광고 없음                                                                                   |
| 콘텐츠 등급      | 설문에서 유틸리티·생산성 선택 → 전체이용가                                                   |
| 타겟층           | 18세 이상 권장. 어린이 포함 시 가족 정책 심사가 추가됨                                        |
| 뉴스 앱          | 아니오                                                                                      |
| 데이터 보안      | 수집·공유하는 데이터 없음. 기기 밖으로 나가는 데이터가 없고 OS 자동 백업은 수집에 해당하지 않음 |
| 정부 앱          | 아니오                                                                                      |
| 금융 기능        | 해당 없음                                                                                   |
| 건강             | 해당 없음                                                                                   |
| 광고 ID          | 사용 안 함                                                                                  |
| 개인정보처리방침 | 공개 URL. App Store 에 쓴 URL 을 그대로 쓰되 안드로이드 항목(안드로이드 달력, 자동 백업)을 추가한 뒤 등록 |

## C. 스토어 등록정보 자산

8. "기본 스토어 등록정보" 에 아래를 올린다. 문구는 사용자가 정하고, 이미지는 `common/store/android/` 에 Claude 가 만들어 둔다.

| 자산              | 규격                                                        |
| ----------------- | ----------------------------------------------------------- |
| 앱 이름           | 30자 이내 (App Store 이름이 정확히 30자 — 제출 때 재확인)    |
| 간단한 설명       | 80자 이내                                                   |
| 자세한 설명       | 4000자 이내                                                 |
| 앱 아이콘         | 512×512 PNG, 알파 포함, 1MB 이내                             |
| 그래픽 이미지     | 1024×500 JPG/PNG, 알파 없음. 사실상 필수                     |
| 휴대전화 스크린샷 | 최소 2장, 최대 8장, 9:16, 한 변 320~3840px                   |
| 태블릿 스크린샷   | 7인치·10인치 각 1장 이상 올려야 태블릿 노출                   |
| 카테고리          | 생산성                                                      |

## D. 앱 서명과 테스트 트랙

9. 첫 빌드 업로드 시 **Play 앱 서명** 사용. 구글이 배포 키를 관리하고 우리는 업로드 키만 보관한다.
   업로드 키스토어(`*.jks`)와 비밀번호는 git 에 넣지 않으며 따로 백업한다.
10. **내부 테스트** 트랙: 심사 없이 즉시 설치 링크. 본인 기기 확인용.
11. **비공개 테스트** 트랙: 테스터 이메일 목록 또는 구글 그룹 등록 → 옵트인 링크 공유.
    테스터가 링크에서 "참여" 를 누르고 **설치까지** 해야 집계된다. 목록에 넣는 것만으로는 안 된다.
12. 12명이 14일 연속 유지. 중간에 빠지면 기간이 다시 시작될 수 있으니 15명 안팎 확보가 안전.
    실제 사용 여부도 본다는 보고가 있어 기간 중 한두 번 빌드를 올리고 써 달라고 부탁한다.
    지인이 가장 확실하고, 상호 테스트 커뮤니티도 있다. 유료 테스터 서비스는 계정 정지 사례가 있어 피한다.

## E. 프로덕션

13. 14일 뒤 "프로덕션 액세스 신청" 이 열린다. 테스터 모집 방법·피드백·수정 내용을 묻는 양식 작성 → 구글 검토 며칠.
14. 승인되면 프로덕션 트랙에 빌드 업로드 → "검토를 위해 보내기". 첫 앱 심사는 하루~일주일. 단계적 출시 가능.
15. 출시 뒤에는 대상 API 36 유지와 연 1회 정도의 정책 변경 대응.
